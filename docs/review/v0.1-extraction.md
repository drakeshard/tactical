# Tactical v0.1 Extraction / Public API Review

TAC-I19 reviews each v0.1 candidate independently after repository-local implementation, composition, serialization, determinism, performance, and cross-module pressure testing.

## Evidence available

Repository-local evidence is strong:

- identity through displacement candidates are implemented and independently tested;
- TAC-I13 found no independently owned sequencing contract and kept sequencing game-owned;
- TAC-I14 composes the surviving modules in a headless first-game-style fixture;
- TAC-I15 verifies plain JSON-friendly state boundaries without a Tactical save service;
- TAC-I16 locks deterministic ordering and tie-breaking;
- TAC-I17 measures representative workloads without identifying a need for optimization infrastructure;
- TAC-I18 composes every surviving candidate together and revalidates dependency boundaries;
- runtime dependencies remain zero;
- the package remains renderer/UI/browser/RPG/Foundation independent.

Production-consumer evidence is not yet available. The current Drakeshard organization repositories are the shared-library/control repositories; there is no production-game repository consuming Tactical. Controlled planning continues to identify the first tactical RPG as the intended pressure-test consumer rather than a current production consumer.

Under the shared-code admission rule, repository-local pressure evidence alone is not enough to admit a stable public gameplay surface.

## Public-surface decision

The valid v0.1 outcome is selected:

- `@drakeshard/tactical` remains `private: true`;
- runtime dependencies remain empty;
- package `exports`, `main`, `module`, `types`, and `typings` remain absent;
- `src/index.ts` remains an intentionally empty stable gameplay export;
- no npm publication is authorized.

Implementation under `src/` remains repository-local incubation.

## Package-name fit

The repository/package track remains named Tactical during incubation, but the surviving implementation is overwhelmingly spatial/battlefield-shaped. Before any stable public gameplay API or publication is admitted, package-name fit must be reviewed again.

Do not rename speculatively now: a real production consumer may demonstrate additional independently Tactical responsibilities or may show that a narrower battlefield/spatial package name is more accurate.

## Dependency review

No runtime dependency is justified.

In particular:

- no RPG dependency;
- no Foundation dependency;
- no renderer/UI/browser dependency;
- no external pathfinding/navigation dependency.

The consuming game remains responsible for cross-library composition and Foundation services around Tactical.

## Next evidence gate

The next meaningful phase is a real production-game consumer.

That consumer should use repository-local/incubation Tactical modules through an explicitly controlled integration path, report API/boundary friction, and provide evidence for candidate-by-candidate admission or further narrowing.

There is no speculative post-v0.1 Tactical feature backlog implied by this review.

## v0.1 conclusion

Tactical v0.1 incubation is complete.

The repository demonstrates a coherent deterministic renderer-neutral battlefield toolkit, but **no stable gameplay API is admitted**. Future extraction/public-surface work is production-evidence-driven.
